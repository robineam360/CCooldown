CCRM-22 · CCRM-23 · CCRM-29 — wireframe for approval

Display tokens: Used/Left, reset display, theme & time mode

Three global display preferences, all landing in Settings → Appearance, each read by every surface from one token — no surface reimplements the choice. Defaults keep today's rendering exactly: Used, Countdown-led, System theme, and time format migrating from the existing 24-hour switch. Nothing moves for existing installs until they touch a chip.

1 · CCRM-22 (Used or Left) — the rule rev B, decided 2026-08-19

One token: usageDisplay = used | left, default used. The governing rule (rev B, per review): every numeric readout flips — worded or bare; fills, ticks and colours never do. Labels flip to "53% left"; bare numbers (ring bores, status-bar icon digits, the number-tile plate) flip to the remaining figure; where a spare line exists the small word "left" disambiguates. The ring's stroke still fills by used — the reviewer accepted that a Left-mode bore states the remainder while the stroke shows the spend. Fills, pace ticks, red segments and the 80/90/100 colour ladder always key on used percent (verified: every Palette.barColor call site passes used%). Rev A's "bare gauges stay on used" was reviewed and rejected 2026-08-19.

2 · CCRM-23 (Reset Display) — countdown or clock, one token, every surface

One token: resetDisplay = countdown | clock, default countdown (today's primary). The tile's tileSubtitle becomes a read of this token — the tile keeps the behaviour, stops owning the preference. The decision this wireframe settles: several surfaces show both forms today (main cards, widget sub-rows, ring faces, expanded notification). Two options, mocked below.

3 · CCRM-29 (Display Mode) — Settings → Appearance, all four controls together

Theme gains a three-way override (themeMode = system | light | dark, default system); the 24-hour switch becomes a three-way (timeFormat = system | 12 | 24). Migration: an install that ever touched the old boolean keeps its explicit choice (mapped to 12/24); only fresh installs get System — nobody's clock flips on upgrade. A forced theme drives everything the system flag drives today: the Material scheme, the chart's per-mode wash/overshoot/fill opacities (0.07/0.10 · 0.18/0.20 · 0.30/0.34), and the status-bar icon appearance (so CCBG-13 (Light Status Bar) stays correct when forced). Widgets and the notification keep following the system — they render on surfaces whose backdrop the in-app override doesn't own.
